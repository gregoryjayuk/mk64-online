# DECISIONS — why online play is built this way

Append-only. One entry per non-obvious choice: date · what · why · what it affects.

- **2026-10-13 · Deterministic lockstep, not state sync.** Both machines run the whole game; only controller input crosses the network (4 bytes per player per frame), delayed by a few frames so it arrives before it is needed. The port has no single memory image to snapshot, so rollback or host-authoritative state would mean serialising hundreds of globals and C++ objects. Lockstep needs the simulation to be bit-identical instead. Affects: everything below.
- **2026-10-13 · Sessions start from a freshly launched process.** The RNG (`gRandomSeed16`) is never seeded and advances every frame from power-on, including during menu rendering, and many statics persist across races. So both games must run every frame from boot together. The Online menu restarts the game (`execv`) with `--host` or `--join`, and the lobby connects before the first frame. Affects: `NetplayGame_Relaunch`, `Game.cpp` main.
- **2026-10-13 · Input goes in at `read_controllers()`, right after `osContGetReadData`.** This runs once per frame, before any simulation, for menus, races, podium and credits alike. The pads for every player are overwritten with the agreed inputs, so edge detection and the OR'd `gControllerFive` derive identically. Affects: `src/main.c`.
- **2026-10-13 · Every machine renders every split-screen view; the renderer shows only its own.** Rendering writes simulation state: actor visibility flags, bomb-kart activity, palm-tree hits, start-line acceleration, and the race-end menus run inside `render_screens`. Skipping the other player's screen would desync. Instead, libultraship's interpreter has a *focus region*: the local player's split-screen rectangle is mapped over the whole window, and draws that fall outside it are dropped. The local camera's projection uses a 4:3 aspect (`gScreenAspect`, read only by projection code), so the stretched view is undistorted. Small rectangles (HUD glyphs) move with the region but keep their size. Focus is on only while a race runs (`RACE_SETUP`…`RACE_CALCULATE_RANKS`); results and menus use the normal split screen. Affects: `libultraship/src/fast/interpreter.cpp`, `src/racing/skybox_and_splitscreen.c`.
- **2026-10-13 · Strict IEEE floating point everywhere** (`-fno-fast-math -ffp-contract=off -fsigned-char`, `/fp:precise`). With fast-math, only byte-identical binaries agree. Strict FP lets a Mac (clang, arm64) and a Linux (gcc, x86-64) build of one commit compute identically, as gameplay trig is table-based. Affects: `cmake/SetFlags.cmake`, the build id.
- **2026-10-13 · Uninitialised memory is zeroed, or made identical.** Members found reading garbage (`AActor` fields, `ATrain`/`ABoat::SomeFlags`, `TrainCrossing::Timer`, `OTrophy::_oldPos`, `OObject::o`) are zero-initialised. Online sessions also restart with `MallocPreScribble`/`MallocScribble` (macOS) or `MALLOC_PERTURB_=85` (glibc), so any leftover uninitialised heap read sees `0xAA` on every machine. Affects: engine headers, `NetplayGame_ParseArgs`.
- **2026-10-13 · Music no longer cuts the cameras online.** `func_800C2274` read cue bytes written by the music sequence on the audio thread. How much audio runs per frame depends on each machine's sound card, and cameras feed the simulation. Online, the cue is ignored: the title demo and finish cinematics just do not cut with the music. Affects: `src/audio/external.c`.
- **2026-10-13 · Host settings and save travel in the handshake.** About 30 gameplay CVars, plus the 512-byte EEPROM (which decides whether the Extra/mirror menu row exists), go from host to joiner and are applied before frame 0. Freecam, debug mode, the editor, look-behind and alternate assets are forced off. The joiner's own settings are restored on exit. Only the host's save is written back. Affects: `NetplayGame.cpp` (`kSharedCVars`), `os_eeprom.cpp`.
- **2026-10-13 · Game data identity = archive contents, not bytes.** Two extractions of one ROM differ in zip timestamps. The content id hashes every entry's name, size and CRC from the central directory, plus the mods folder listing. Affects: `ContentId()`.
- **2026-10-13 · NAT traversal by hand, signalling over ntfy.sh, no servers of our own.** Candidates are LAN addresses, plus the public address learnt from public STUN (Google, Cloudflare), plus IPv6. Both sides probe all of them at once (hole punching) and keep the best answering path. The room code maps to a public ntfy.sh topic (HTTPS through the `curl` CLI, payload scrambled with a key from the code), so players exchange only an 8-character code. A copy-paste connection code and direct `IP[:port]` are the fallbacks. No relay yet. Affects: `Signal.cpp`, `Stun.cpp`, `Netplay.cpp`.
- **2026-10-13 · Audio: each machine hears its own camera.** In split-screen, P1's sounds are hard left and P2's hard right. Online, the local listener's sounds use the one-player stereo pan, and sounds owned by the other camera are muted. This is audio-only state. Affects: `func_800C16E8`, `func_800C19D0`.
- **2026-10-13 · Two players.** The protocol and UI handle a host plus one joiner. Three or four would need host-relayed input fan-out and the 3P/4P focus layouts. Affects: `kMaxPlayers`.
- **2026-10-18 · A public snapshot, not the history.** A public snapshot was prepared for github.com/gregoryjayuk/mk64-online on 2026-10-18: the `netplay` branch as one commit on the upstream base, excludes per docs/PUBLISHING.md. The libultraship changes go to a fork as one commit too, and the public `.gitmodules` points there. Why: the private commit messages and machine notes stay private, and strangers can clone with submodules. Affects: `.gitmodules`, `tools/netplay/public-snapshot.sh`.
